Reservation ownership follows capacity changes and transfer to a weak-domain charge. Failed growth leaves the ownership ledger unchanged; final release clears the remaining capacity in the same ledger update. Shared cache directory shells remain reader-owned after payload eviction, while upgraded reclaimer handles carry operation pins.

Linear and summary readers accept the domain at construction, without allocating discarded default domains; their construction with a pre-existing domain performs no heap allocations. The summary parser control uses an exactly charged box. Parser domains are selected before input allocation or state advancement and cannot subsequently be replaced. Partial-summary fallback scanning inherits the reader domain and record-length limit before requesting input; refusal restores the source cursor and releases its parser. Selecting the same domain remains valid. Indexed readers fix their domain during construction; summary resets retain that domain, and chunk codecs receive it before initialization.

Shared payload references carry parser, pending, operation, cache or lease ownership. Cache access acquires an operation pin while holding its cache lock, including descriptor pages; eviction removes cache ownership without invalidating that pin. These counters establish eligibility for the tracked storage, but control blocks, remaining nested storage and the wait-ticket protocol still require integration before the domain-wide closure is complete.

The test-only `allocation-audit` feature reports explicit allocation identities to an independent fixed-capacity system-allocator probe. The probe matches pointers and allocation sequence numbers, checks live category capacity and cumulative allocation counts/bytes, and observes deallocation independently. Run the identity test in isolation to interpret unattributed allocation counts; concurrent tests contribute unrelated allocator events. Unattributed allocations remain an open closure requirement, even when every reported identity matches. The feature is enabled only by the native dev-dependency and does not provide production accounting.


Shared segmented index roots, directories and data pages retain Parser or Operation pins. New nodes acquire their pin before publication; existing nodes remain pinned through growth and failed allocation rollback. Clones register unique storage capacity, with writer and reader owner classes kept distinct. Nested values require their own accounting and ownership; charging a directory does not establish accounting for its contents.

Shared summary schemas and channels retain exactly charged text, schema bytes, shared controls and paged metadata. Writer completion and SummaryReader parse/serialize these directly; shared clones preserve content after writer disposal. Truncation/malformed-input differential tests, per-allocation refusal and cross-page metadata lifetime tests cover these paths. Sequential and buffer readers, including lease engines, retain the same exact shared declarations and pin their lookup pages as Parser storage; obsolete declaration estimates are removed. Sequential wire schema IDs remain independent of resolved schema references, preserving records-only scans and comparison with preloaded summaries. Declaration refusal after record consumption is terminal. Ordinary Rust owned helper exports and JSON output temporaries remain unfinished. Independent full-writer fixtures reconcile every allocation for None/Lz4/Zstd with explicit thread counts and a pre-existing domain; this does not establish closure for default domain bootstrap, error responses or all reader paths.

Capacity-ticket storage is an exactly charged stable node allocated before the operation that may wait. The domain ledger owns only intrusive links; ticket disposal unlinks under the ledger lock before releasing storage. Registration checks capacity under that same lock, and sufficient release latches readiness even if another operation immediately occupies the bytes. Idle-pool and cache-only storage contribute reclaimable capacity. Registration, inspection and cancellation allocate nothing, including refusal and invalidated-wait error construction. Ticket creation and admission propagate fixed StorageFailure values through ABI encoding; exhausted-budget and injected allocator failures require no error heap storage. The async lease engine preallocates its ticket and registers after rollback. Retry demand includes exact descriptor pages and controls; managed waiting subscribes, checks the latched ticket, and unregisters on cancellation. Capacity changes enqueue domain notifications without occupancy comparisons. Admission compares the complete retry demand with unique externally releasable capacity; an unrelated small lease cannot justify waiting. Finite lease/cache destruction, charged control/tree/slice disposal, operation-pin release and idle-block reclamation protect the interval between removing ownership and physically returning storage. Destruction scopes also end during unwinding; surviving weak controls remain charged and do not justify indefinite waiting. Strict tickets reject insufficient external capacity once these scopes end. Charged budget handles contain registry links, listener state and coalesced pending-notification links. A native-only ledger observer queues just the changed domain; bounded dispatch invokes callbacks outside ledger and registry locks. Disposal clears the observer before unlinking and freeing its handle. Requester-specific operation ownership remains unfinished; this is not yet the complete waiting protocol.

Fixed-result control allocation and paged append/insert paths preserve structured reservation failures without boxing an I/O error. Borrowed string-map validation, retained declarations and indexes, declaration publication and summary index publication use these paths. Independent probes exercise real capacity limits, including a one-byte deficit, as well as injected allocator failures; they reconcile physical allocations and verify rollback of capacity and owners. Compatibility I/O adapters at unconverted call sites still require closure.

Shared summary controls, cache controls and reclaimer registry pages use fixed-result allocation transactions. Cache index/entry publication and writer canonical keys also propagate fixed failures without the compatibility I/O bridge. Independent probes exercise actual capacity refusal and injected allocator refusal, including weak-control retention and registry-page rollback. Random chunk setup borrows the compression name and shares payload-bound validation with owned parsing; successful header parsing and truncated-header error encoding require no native heap allocations. Unsupported-compression diagnostics and the remaining I/O adapters are still open accounting paths.

Indexed metadata and attachment reads parse caller indexes into exactly charged shared records, then validate the indexed range through the official parser using shared input. They do not materialize an owned record or clone its payload. Differential tests cover truncation, mutations, CRCs and extra records; an independent allocation probe includes an 8 MiB attachment and injected allocation refusals. Caller-buffer delivery counts only successful copies, not capacity-probe retries.

Snapshot configuration uses an allocation-free budget-ID scan before building its charged JSON document. The scan decodes escaped keys and applies last-value replacement for duplicate keys, with bounded recursion and fixed errors. Copied, mapped and reader-derived snapshot entry points use this path; full-file validation parses its control document in its default domain. Real-capacity rejection and independent allocation identity tests verify selection precedes document allocation. Numeric JSON error construction remains open. Indexed preflight scans store chunk offsets and lengths in charged pages with binary search and duplicate-use markers instead of an uncharged tree.

Writer creation selects its domain before parsing the charged configuration document. Retained profile/library text has exact byte and shared-control allocations with Operation ownership; cloning the native options shares that storage. Domain mismatch is rejected before writing the file header. Independent probes reconcile constructor/document/text/control allocations and each injected failure; real-capacity tests cover text refusal and constructor rejection before output. Initialization peak includes temporary JSON pages, so a budget sized only for post-construction occupancy can reject construction. The original Rust infallible string setters remain compatibility APIs; the binding uses the fallible charged setters. Reader and engine configuration follows the same charged-document rule.

Indexed-reader selected channel IDs use lazily allocated 256-entry u16 pages with Parser ownership. The former per-channel multiplier reservation and uncharged channel-ID tree are removed. Cross-page selection, injected page failure and independent allocation-identity tests verify actual live capacity with no unused estimate. The original Rust caller option topic-name set remains caller-owned.

Indexed-reader construction can evaluate a borrowed topic predicate synchronously and retains only the resulting charged channel-ID pages. The native sequential reader reuses its existing filter when preparing indexed access, avoiding a cloned topic-name tree. Retained topic strings and constructor JSON use charged storage.

Indexed chunk/message/slot page appends and native cache capacity reservations propagate fixed allocation failures. Real-capacity tests cover temporary and permanent rejection through ABI encoding without error heap allocation. Storage and parser compatibility I/O adapters not converted to fixed results remain open.

## Codec failure contract

The pinned zstd-sys source preserves the configured worker count. Its reviewed patches reject null custom allocations before clearing memory, preserve custom allocator identity during partial pool initialization, and avoid traversing a missing job table during cleanup. Patch fingerprints include these C sources and the build-script dependency on the source directory. Both the production crate and standalone MCAP tests use this same patched codec version.

Allocation failure inside a codec is terminal. The callback never waits for a consumer or invokes managed code. Tests reject each observed allocation attempt and verify codec workspace occupancy returns to zero after context teardown; a live domain retains its root control. System allocator failure and domain refusal are separate errors; fixed codec failures reach the ABI with resource, capacity, phase, failure-kind and terminal details.

## Acceptance boundary

The current inventory does not establish a complete heap ceiling. Finish every open accounting item, domain wait tickets and complete ownership statistics before removing that limitation. OS thread stacks/runtime resources, allocator fragmentation, managed/caller buffers and mapped resident pages remain separate from the controlled heap budget.

Linear parser input growth, shared-input relocation and decompression storage reservation propagate fixed storage failures. Writable bounds are published only after successful allocation. Tests cover capacity refusal, overflow, preserved input and writable ranges, retry after released capacity, and independent allocation identities through ABI error encoding. Remaining codec/I/O compatibility adapters and cold diagnostics still require audit.

Reader creation selects the budget before parsing configuration. Retained topic strings have exact byte capacity and Parser ownership; topic lookup uses sorted paged descriptors. Engine creation also uses charged configuration, preserving summary-domain inheritance when indexed-engine Memory is absent or null, including duplicate and escaped keys. Indexed engines evaluate a borrowed filter and retain selected channel IDs rather than a topic-name tree. Initialization requires room for temporary configuration pages in addition to retained state. Copied and mapped buffer-reader configuration also selects its domain before charged parsing; the copied constructor has independent allocation identity and per-allocation refusal coverage. Temporary reader configuration is released before indexed preparation or buffered sorting, and mapped configuration before parser construction. Numeric JSON error construction remains open.
